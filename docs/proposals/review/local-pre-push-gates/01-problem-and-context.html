Why the gate caught this is correct (the contract is right)

The sync contract is real and load-bearing:

  • "Closes #N against a closed issue" is a stale ref — the work is no longer owed, the PR description lies.
  • "Bare #N against a closed issue" is ambiguous at best — the contributor linked to an issue that doesn't accept contributions.
  • The gate's job is to surface the contradiction at PR time, not at merge time.

The bug is not the gate. The bug is that:

  1. The local developer got no signal.
  2. The gate does not distinguish between Closes #N (closed) (genuinely stale) and Related to #N (closed) (intentional audit-trail preservation).

Cost profile (why per-push LLM judges are non-starter)

Adding the provider-token cost of all blocking gates per push (the headline metric; wall-clock shown for context):

  • test + validate + lint: ~2m30s wall-clock, $0 tokens
  • cache-decay-audit (G4+G5): ~2m12s, $0 tokens
  • prompt-injection static filter: ~10s, $0 tokens
  • /dev-kit:review (3-dim): ~1m44s, ~$0.10-0.50 per push
  • /dev-kit:security (10-dim): ~2m22s, ~$0.50-2.00 per push
  • /dev-kit:maintenance: ~3m45s, ~$0.30-1.00 per push
  • issue-sync: ~9s, $0 tokens (uses gh api)

Total deterministic cost per push: $0 (no provider tokens) Total LLM-judge cost per push: ~$1-3.50

Running LLM judges per push is 2-3 orders of magnitude more expensive than the deterministic subset in provider tokens, and the only metric that matters for this proposal. Wall-clock is secondary. The migration matrix must reflect this.
