# Token dashboards

Canonical home for the per-repo HTML dashboards generated by
[`tools/token_efficiency_analyzer.py`](../../tools/token_efficiency_analyzer.py).

## Layout

Files generated by the analyzer land here by default:

| Window     | Path                                                  |
| ---------- | ----------------------------------------------------- |
| 30 days    | `dashboard-30d.html`                                  |
| 30 days, transcripts sidecar | `dashboard-30d-with-transcripts.html`  |
| 30 days, no transcripts     | `dashboard-30d-notx.html`              |
| 3650 days  | `dashboard-3650d.html`                                |

Each `.html` may have a sibling `.assets/` directory containing the lazy
transcript drill-down sidecars (per-worktree → per-session raw transcripts).
Both the `.html` and the `.assets/` directory are gitignored — they are
regenerated locally by the analyzer and never committed.

## Generating

The analyzer is invoked by the [`/dev-kit:token-analyzer`](../../skills/token-analyzer/SKILL.md)
skill (read-only). With no flags it writes to this directory; pass `--out
<path>` to redirect (e.g. for ad-hoc archives).

```bash
# Default 30-day window, with transcript drill-down sidecars
python3 tools/token_efficiency_analyzer.py --repo dev-harness-kit --days 30

# Custom output path (still gitignored at any location)
python3 tools/token_efficiency_analyzer.py --repo dev-harness-kit --days 30 \
    --out docs/observability/dashboard-30d.html
```

## Why here, not repo root

Before this directory existed, the analyzer's default output was
`token-dashboard-<repo>-<days>d.html` at the repo root, gitignored but
still visually polluting the top of `ls`. Moving the default here makes
"where do dashboards live?" answerable from `docs/` alone — the
`docs/observability/` family already hosts the long-form prose for
`token-efficiency.md` and `session-monitor.md`, so dashboards belong
in the same neighborhood.

## Performance

Per-worktree classification (`classify_all_worktrees()` in
[`tools/token_efficiency_analyzer.py`](../../tools/token_efficiency_analyzer.py))
spawns 3 git subprocesses per worktree dir
(`rev-parse --short HEAD`, `rev-parse HEAD`,
`log origin/main..HEAD`). On a checkout with thousands of `.worktrees/*`
+ legacy `.claude/worktrees/*` + `.codex/worktrees/*` dirs (the dev-harness-kit
checkout has ~1,500), the loop is fanned out across a bounded
`ThreadPoolExecutor` so wall time scales as `n_dirs / max_workers` rather
than `n_dirs * 3`. Two repo-wide probes (`git worktree list --porcelain`,
`git rev-parse origin/main`) stay hoisted and run exactly once per
dashboard. The `--no-include-worktree-logs` flag is the escape hatch
when a `git worktree list` is too slow; it scopes the analyzer to the
top-level `logs/` only and skips per-dir classification entirely.
