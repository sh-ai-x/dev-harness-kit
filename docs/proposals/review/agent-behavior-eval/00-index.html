TL;DR

에이전트가 "의도대로 정확하게 해결했는지"를 자동으로 평가하기 위해 7차원 루브릭 + worktree 로그 기반 trajectory 인프라를 도입한다.

핵심 결정:

  • 데이터 소스 = worktree 로그 (git, hooks, hand-off, eval transcript). 모두 disk 에 이미 존재
  • 결정적 70% (D1-D4) + LLM 30% (D5-D7) — 빠르고 재현 가능한 평가
  • PR gate = 상대 변화 (baseline 대비 diff), 절대 점수 threshold 사용 안 함
  • 신규 인프라 0, 신규 vendor 0, 신규 의존성 0

배경 — 왜 필요한가

기존 /dev-kit:evaluate 는 final-output rubric 만 채점한다. 에이전트의 행동 자체를 평가하지 못한다:

  1. ROT verdict 시 원인 파악이 수동 — transcript 열어보고 재실행
  2. 회귀 분석 불가능 — harness 버전 간 행동 변화 자동 추적 없음
  3. judge variance 디버깅 막힘 — 분산 > 0.5 일 때 judge 가 본 것 추적 어려움
  4. 비용 / 지연 가시성 없음 — 어떤 step 이 비싼지 알 수 없음

본 proposal 은 4 가지 사각지대를 worktree 로그 = trajectory 로 메운다. 새 telemetry 인프라 없이.

핵심 아이디어 (한 문장)

worktree 1개 = 작업 1건 = 평가 단위 1개. 이미 disk 에 있는 git/hooks/hand-off/eval-transcript 를 append-only JSON 으로 정규화하고, 7 개 차원 점수 = trajectory score.

#차원무엇결정성가중치

D2Process Conformance절차 준수 (commit 형식, branch, hooks firing)✅15%

D5Communication Qualityhand-off 노트 / PR description 명확성⚠️ LLM10%
D6Robustness에러 주입 시 graceful recovery⚠️ 시나리오10%
D7Trajectory Quality도구 선택 / 순서 합리성⚠️ hybrid10%

결정적 70% 가 LLM 없이 평가 → CI 게이트로 바로 사용 가능.

비목표 (Out of scope)

본 proposal 은 다음을 포함하지 않는다:

  • 외부 observability 플랫폼 도입 (자체 인프라로 충분)
  • eval case 수 확장 (현재 12 case 유지)
  • prompt engineering 작업 (judge prompt 는 별도 제안)
  • production telemetry / OpenTelemetry 통합 (필요 시 별도)
  • multi-tenant eval infra 공유 (팀 규모 10+ 시점에 별도)

성공 지표 (3-6 개월)

  • CI gate 결정적 차원 4 개 (D1-D4) 가 PR 마다 자동 평가
  • per-dim breakdown 항상 노출 → ROT 원인 즉시 파악
  • 회귀 자동 탐지 — 동일 spec 의 2 회 run 사이 diff 자동 알림
  • 신규 의존성 0 — lib/ + tools/ + eval/ 내부 파일만 추가
