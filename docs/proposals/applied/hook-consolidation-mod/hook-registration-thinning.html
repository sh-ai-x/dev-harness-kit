Decision

Adopt the dispatcher only at the event-registration boundary. The SessionStart children continue to own their behavior and can still be executed and tested independently. The dispatcher is a thin adapter: it reads the runtime payload once, fans it out, ignores unavailable or malformed child output, and always returns a valid SessionStart envelope.

Merge matcher groups only where the matcher semantics are identical.

The combined Write|Edit|MultiEdit|Bash ask group preserves the

existing destructive-confirm decisions. Keep the Agent and WebFetch injection groups separate: sub-agent-handoff is intentionally limited to Agent responses.

Verification

The reduced manifests are valid JSON and remain parity-compatible. The focused hook suite covers the dispatcher, registry counts, matcher wiring, guard defaults, active-hook regeneration, and retained guard behavior.

203 passed, 66 subtests passed in 137.67s across the focused hook, guard-mode, harness-mode, executor, and wiring suites.

The measured result is 27 registered command entries per runtime, down from the 36-entry baseline.

Future reduction rule

A later reduction should first prove that two hooks have identical event, input, output, failure, and state contracts. If they do not, keep them as separate child modules and reduce only their registration boundary. Any process-level merge must add an isolated failure test before it replaces a child script.

Before / After

Before (current state)

The two runtime manifests registered the same lifecycle behavior through eight independent SessionStart commands. One matcher repeated the same destructive-confirm registration for Write-family tools and Bash. This made the manifest larger, increased registration bookkeeping, and made runtime parity harder to audit even though the underlying contracts were already shared. A prompt-time LLM TDD judge also duplicated the deterministic edit guard and added a model/network path to every prompt.

Evidence

  • hooks/hooks.json at baseline registered 36 command entries, including 8 SessionStart entries and one prompt-time TDD judge.
  • .codex-plugin/hooks/hooks.json carried the same 36-entry shape for the Codex runtime.
  • tests/test_hooks_json_parity.py treats both manifests as a parity pair, so registration drift is a cross-runtime risk.

After (proposed state)

Reduce registration surface without removing retained safety or lifecycle behavior. A single SessionStart dispatcher reads the payload once, invokes the existing child modules, and combines valid advisory context. The duplicate destructive-confirm matcher registration is represented once; channel-specific injection matchers remain separate to preserve behavior. The redundant prompt-time TDD judge is removed; unknown code paths require RED evidence unless .dev-kit/.tdd-scope.json explicitly opts them out. Both manifests stay aligned, and child scripts remain directly testable.

Pros

  • Cuts registered command entries from 36 to 27 per runtime and SessionStart registrations from 8 to 1.
  • Preserves child behavior, fail-open boundaries, Claude/Codex parity, and focused test seams.
  • Removes duplicate destructive-confirm matcher bookkeeping without adding a new policy or recurring prompt.
  • Removes the prompt-time LLM TDD judge and keeps the RED-evidence rule local and deterministic.
  • Keeps the default-off guard policy and prior thin-harness deletions intact.

Cons

  • Child checks still run inside the dispatcher, so registration count falls without removing their per-session work.

Limitations

  • Further process-level consolidation is deferred to avoid coupling independent fail-closed contracts.
