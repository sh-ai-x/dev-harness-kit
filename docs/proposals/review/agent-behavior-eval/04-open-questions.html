본 proposal 이 답하지 않는 것

다음 항목들은 의도적으로 deferred. 각 항목은 별도 proposal 또는 Phase 2 이후 작업으로 다룬다.

Q1 — LLM judge absolute anchor (auto-calibration)

문제: D5/D7 LLM judge 의 절대 점수 (예: "5 의 의미") 가 calibration 없이 정의되지 않음.

현재 완화: PR gate = 상대 변화만 (baseline 대비 diff). 절대 threshold 사용 금지.

후속: anchor exemplars (hand-off note 10 개를 gold/silver/bronze tier 로 hand-PICK, 채점 아님) + cross-model consensus + synthetic validation. 사람 채점 없음. Phase 1 후속 또는 별도 proposal.

트리거: judge 점수가 PR gate 에서 사용되어야 할 필요 발생 시.

Q2 — Cross-worktree batch eval (consistency)

문제: 단일 worktree 평가만으로는 에이전트 일관성 측정 불가. "이번 prompt 변경이 에이전트를 더 일관성 있게 만들었나?"

현재 완화: 단일 worktree 평가만 지원.

후속: tools/replay_regression.py 로 동일 spec 을 N=5 worktree 에 실행, per-dim variance → consistency score. Phase 2.

Q3 — Trend tracking (시간에 따른 drift)

문제: 에이전트가 좋아지고 있는지 나빠지고 있는지 추세 모름.

현재 완화: per-worktree 점수만 기록.

후속: .dev-kit/agent-behavior-history.jsonl 누적, 1 주 단위 윈도우 평균 시각화. Phase 2.

Q4 — New dimensions (D8/D9)

문제: 7 차원 외에 평가해야 할 차원이 있을 수 있음.

후보:

  • D8 Reversibility — commit 이 작은 단위로 분리되어 revert 가능한가
  • D9 Side-effect Awareness — task scope 외 파일 변경 (lock 파일, secret-shape 등)

현재: 미포함. 7 차원 도입 후 운영 데이터 보고 결정.

Q5 — Test-weakening detector

문제: 테스트가 통과해도 의미 없는 변경이 가능 (coverage 감소, assertion 제거, mock 남용, test skip 추가).

후속: lib/behavior_scorers/test_weakening.py — 5 신호 (coverage drop, assertion diff, mock/skip 도입, test file 삭제). D1 의 sub-detector 로 통합.

트리거: 실제 false-positive 사례가 발견되어 측정 필요 시.

Q6 — Scenario fixtures (D6 robustness)

문제: D6 robustness 의 5 개 시나리오 (compile-error, flaky-test 등) 가 실제 실패 모드와 어떻게 매칭되는지 미검증.

현재: placeholder fixture (v1), 실제 시나리오 생성은 v2.

후속: 실제 ROT verdict 가 떴던 worktree 의 transcript 를 분석 → D6 fixture 로 promote. 인간 review 후 머지.
