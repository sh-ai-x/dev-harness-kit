Open questions

  1. Should `Issue #N` be added to `_REF_KEYWORDS`? - PR #829's body used Issue #N (not Related to #N). - If we don't add it, the lenient branch doesn't fire and the PR still fails — which defeats the purpose. - Recommendation: add it. It's case-insensitive and matches GitHub's web UI behavior (which counts Issue #N as a reference). Document the addition in tools/issue_sync.py docstring.
  1. Should `pre-push` subcommand accept `--from-pr <N>` to skip `git log` parsing and use the PR body directly? - Pros: same code path as the remote gate (single source of truth). - Cons: requires gh pr view --json body which adds a network call we want to avoid in --offline mode. - Recommendation: support both. --from-pr <N> is the default for the remote workflow (after push). --from-log is the default for the local pre-push hook (no network).
  1. Should `cache-decay-audit` G4+G5 ship in Phase 1 or Phase 2? - Pro Phase 1: it's deterministic, ~30s, catches real bugs. - Pro Phase 2: it's a separate concern from the issue-sync fix and can ship independently. - Recommendation: Phase 2. Phase 1 ships the minimum hook that would have caught PR #829's bug; Phase 2 covers the rest of Tier A.
  1. Should `bin/review-local.sh` replace `/dev-kit:review-local`? - Pro: bin/review-local.sh is already a wrapper; the skill adds LLM-judge ergonomics on top. - Con: skill vs script is a known pattern in this repo (skills add value-judgment; scripts are deterministic). - Recommendation: keep both. Skill is the human-facing entry; script is the engine.
  1. Does the local hook need `gh auth status` to run? - For gh api (issue-sync, linear-sync): yes. - For pytest/ruff: no. - Recommendation: if gh auth status fails, run the hook in --offline mode and emit a ::notice explaining why state isn't verified. Developer can re-push after gh auth login.

The closest analog is workflow-fast-mode/. Both proposals target per-push cost, but from different angles:

  • workflow-fast-mode/: reduce the GH Actions runtime by slimming the workflow definitions.
  • local-pre-push-gates/: reduce the rate of red pushes by catching failures locally.

Both proposals are complementary — neither invalidates the other.
