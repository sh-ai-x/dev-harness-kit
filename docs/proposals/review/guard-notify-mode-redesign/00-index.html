Decision and scope

Adopt the channel-split hook contract: every hook's hookSpecificOutput.additionalContext is byte-stable for a given (file_class, hook_name, branch_class). Operator-only data (full worktree list, full RED log, debug dumps) is written to stderr the LLM does not see.

Scope:

  • PR 1: hook channel-split + timeout: ban + context-window-guard rewrite + CI wiring.
  • PR 2: tdd-scope-classify relocated to lib/tdd_classify.py, invoked by /dev-kit:build-tdd.
  • PR 3: /dev-kit:cwd skill, replaces session-start-worktree-cut.sh.

Out of scope (this proposal explicitly does NOT defer them — they are addressed in PR 1/2/3 above):

  • context-window-guard.sh bug — addressed in PR 1.
  • /dev-kit:cwd skill — addressed in PR 3.
  • Closing PR #836 — addressed via Closes #836 in PR 1.

Root cause — the LLM consumer is missing today

Today's hooks were designed assuming the operator would see stderr and reason about it. When Claude Code's PreToolUse returns a deny JSON, that JSON enters the tool-result channel on the next LLM turn and becomes part of the user-message prefix for the turn after that. Per rules/session-hygiene.md Iron Law 3, volatile content in the user-message prefix busts the prompt cache.

Concretely:

  • worktree-guard deny emits 30 lines of variable worktree paths through stdout. Each retry-after-deny turn pays full input-token cost for a payload the LLM cannot usefully act on.
  • tdd-guard deny emits a 1-line message on the deny path only. On the happy path the LLM sees NOTHING about the RED-evidence contract; the contract has to be in the system prompt or learned from a deny. Both are worse than a deterministic additionalContext emit.

The fix is not "delete the slow hooks" (PR #836's approach) nor "make every hook allow and never deny" (a non-fix). The fix is to author hook payloads with the LLM as the consumer in mind: stable, byte-for-byte reproducible across retries, and present on the happy path so the LLM learns the contract before the deny ever fires. Operator visibility is preserved by routing operator-only data to stderr.

Hook timeout fragility and the silent-discard problem

Claude Code's hook execution has a hard cap of 10 seconds. When exceeded, the hook's stdout is silently discarded and the LLM proceeds with no contract reminder. The user-visible error is:

"UserPromptSubmit hook timed out after 10s — output discarded. Raise the hook's timeout to allow more time."

This message is a misdirection. The two ways to "fix" it are both wrong:

  1. Raise the `timeout` field — does not work. The cap is a Claude Code platform limit, not a per-hook setting. A timeout: 120 in hooks.json is theatre: any work past the cap is invisible to the LLM.
  2. Move the work to a different event — partial fix. If the work is intrinsically slow (LLM judge, full-file scan), no event surface makes it cheap. The work has to leave the hook path entirely.

The right principle is: a hook must complete in under 10s on the critical path, or it is not a hook. Anything slower belongs to one of three locations:

  • Skill entry (SKILL.md step 1) — invoked when the user runs /dev-kit:build-tdd. Result persisted to disk; the hook reads the cached file. This is PR 2 of this proposal.
  • SessionStart — runs once per session, off the per-prompt critical path. Acceptable for setup work that does not need per-Edit freshness. PR 2 uses this for the .tdd-scope.json nudge.
  • Pre-commit / CI — runs out-of-band. Acceptable for enforcement that does not need to teach the LLM. PR 1 uses this for the timeout: lint.

The corollary: the timeout: field in hooks.json is banned. PR 1 hard-rejects the key on any event.

Channel-split hook contract (LLM channel vs operator channel)

Every hook satisfies:

  1. The hookSpecificOutput.additionalContext field, when emitted, is byte-stable for a given (file_class, hook_name, branch_class) input triple.
  2. Operator-only data (full worktree list, full RED log, environmental debugging info, anything the LLM does not need to read) is written to stderr ONLY. Claude Code does not surface stderr to the LLM.
  3. The permissionDecision field is one of "allow" (with additionalContext carrying the reminder) or "deny" (fallback only when the contract is genuinely violated AND no bypass is active).

Stable prefix is asserted by hashing the additionalContext string across N runs with the same input triple; if the hash differs, the test fails.

The split is visible in the contract:

.---------------------------------------.
| LLM channel (stdin/stdout to tool)    |
|----------------------------------------|
| hookSpecificOutput.additionalContext | <- byte-stable
| permissionDecision     : allow | deny |
'----------------------------------------'

.---------------------------------------.
| operator channel (stderr to terminal) |
|----------------------------------------|
| git worktree list --porcelain        |
| full RED log dump                    |
| debug env, branch worktree state     |
'----------------------------------------'

Operator visibility is preserved (stderr still has the full worktree list); the LLM sees only what it needs to read.

Acceptance criteria

All three PRs land with green CI (review, security, maintenance). The proposal is accepted when:

  • tests/test_hook_additional_context.py, tests/test_no_hook_timeouts.py, tests/test_context_window_guard.py, tests/test_tdd_classify_move.py, and tests/test_cwd_skill.py all pass with deterministic hashes.
  • The Closed-questions table is fully self-resolving; no item is left as "deferred to follow-up."
  • One production session demonstrates cache-hit improvement on retry-after-deny turns.
  • Operator can demonstrate /dev-kit:guard-mode off toggling back to enforcement on the next Edit.
  • Operator can demonstrate /dev-kit:cwd running, suggesting a slug, and cutting a worktree without ever invoking git bash directly.
  • PR 1 carries Closes #836 and the operator merges it.

Reviewers should reject the implementation if:

  • The byte-stability assertion does NOT pin the actual emitted string (substring assertion is not enough).
  • The channel-split is reintroduced as >>/dev/stderr appended to stdout.
  • _worktree_list_rich() is removed entirely (operator visibility regresses).
  • The timeout: ban regresses to a >5s lint (any ban is better than none, but the proposal's principle is "no timeout at all").
  • The session-state machine is reinvented instead of reusing lib/guard_mode_state.py.
  • PR 2 lands before PR 1 (order dependency).
  • PR 3 lands before PR 2 (order dependency on /dev-kit:build-tdd classify chain).

Before (current state)

PR #836 (fix/remove-userpromptsubmit-advisories) deleted three hooks — worktree-auto-cut, tdd-scope-judge, context-window-guard — because they were slow on UserPromptSubmit. Two of the three were restored in the review cycle (commits 4114eb49, 1262849a), but the underlying contract problem is unresolved: hooks were authored for the operator consumer, not the LLM consumer. Review verdicts on both 5832b907 and 4114eb49+1262849a are Blocked on review / security / maintenance.

Four concrete symptoms:

  1. hooks/worktree-guard.sh:128-140 runs git worktree list --porcelain and embeds the full output in the deny JSON's stdout channel. With ~220 worktrees on the dev-kit admin's machine, the deny payload is ~30 lines of variable path content. Per rules/session-hygiene.md Iron Law 3, volatile content in the user-message prefix busts the prompt cache on every retry after a denial. The LLM reads the payload, finds no actionable signal, and emits the same Edit call again.
  2. hooks/tdd-guard.sh:30 calls python3 -m lib.tdd_scope_policy on every Edit. Classification should happen at build-step entry, not at hook time. The Python cold-start cost is the actual latency that triggered the UserPromptSubmit complaint in #836; moving it to the hook is not a fix.

Claude Code's documented hard cap on hook execution time is 10s. When exceeded, output is silently discarded and the LLM proceeds with NO contract reminder. A timeout: 120 setting is theatre: any work past the cap is invisible to the LLM. Either the hook completes in <10s on the critical path or it does not belong on the hook path.
