1. Measurement population and window

The controller enrolls an expected unit before dispatch, separately from the event emitter. Identity is (root_id, run_id, workflow_id, subject_id, attempt_id). root_id is the canonical absolute payload project/worktree path, never git-common-dir/..; module lookup uses the installed plugin root separately. Missing/ambiguous root is COLLECTION_ERROR, not fallback to the main checkout. Retries have distinct attempt IDs. Enrollment records producer/version, expected terminal family, start time, deadline, origin and source revision.

Cohort is the set enrolled in a UTC half-open interval [start, end), scoped to one root and origin (runtime or ci-probe). Default runtime interval is the UTC day of enrollment; active and prior unfinalized days are refreshed automatically. Terminal events after end still join the enrolled unit through collected_at. Units are pending until explicitly closed or their lease expires. Pending units are shown separately and never silently counted as failures or successes. A cohort is final only when it has no pending units; late events create a new revision that supersedes the old result and marks late evidence explicitly.

Eligible denominator = enrolled closed or expired units. Numerator = eligible units with a valid start and exactly one semantically consistent observed terminal. Failed and blocked terminals count as observed closure, not success. Report enrolled, pending, eligible, paired, missing_start, missing_terminal, conflicting_terminal and unexpected_event_units separately. Unenrolled events cause degraded readiness and never silently enter a successful numerator. Empty eligible population means NO_OPPORTUNITY with ratio=null.

Runtime coverage policy defaults to 0.95; it is an explicit policy choice, not a statistically established boundary. Minimum eligible sample is 20 for runtime READY; smaller samples are INSUFFICIENT_EVIDENCE with raw ratios shown. Both values and a policy version are stored in the envelope. CI probes use their exact manifest and require 100% of expected observations, independent of the runtime policy. Neither origin is pooled with the other.

A single per-worktree monitor runs while enrolled units remain active, checks every 60 seconds, and coalesces collection to at most once per 60 seconds except terminal boundaries. Default lease is 15 minutes; adapters renew at most every 60 seconds while their owner process is live, including during long tool calls. Record the stable runtime/session owner PID plus process start identity to avoid PID-reuse confusion, never the ephemeral hook shell/Python PID. Each adapter must validate a stable owner token; unavailable ownership is UNSUPPORTED. Cross-process hooks exchange persisted registry state; no context manager spans them. A same-process executor may use finally for catchable exits, preserving original exceptions and outcomes even if all telemetry operations fail.

A monitor crash is restarted at the next hook/CLI boundary. Collection records freshness and monitor health; snapshots older than 5 minutes are STALE for an active cohort. Closed snapshots remain valid historical observations and show their cutoff rather than pretending to be a current live measurement. Supported adapters must prove their enrollment and callback behavior in CI; otherwise their readiness is UNSUPPORTED. Missing entire enrollment cannot be inferred from an empty trace alone, so readiness also requires a producer manifest/version and a successful capability probe for that adapter version.

3. Coherent storage and snapshot contract

Store registry and collector outputs under <root>/.dev-kit/trace. One advisory lock coordinates strict lifecycle writes, enrollment, registry transitions, raw trace capture and archive updates. Failure to acquire the lock within two seconds produces COLLECTION_ERROR and a bounded error record; do not continue unlocked or replace a valid snapshot with a misleading empty one. Hooks preserve workflow exit status, while the collector CLI returns 2 on collection errors and CI treats that as failure.

Semantic key is (unit identity, lifecycle transition); a retry with identical content is a no-op returning the original event identity. Different terminal content for the same unit is a conflict finding, not regenerated success. Legacy writers lacking this contract are identified as legacy provenance. Copy raw bytes plus registry revision under lock, then reduce that immutable capture. Preserve malformed rows in the capture so integrity sees them. Publish only if its capture sequence is newer than latest; a slow older collector must not overwrite a newer result. Record source byte length and SHA-256, registry revision and policy version for reproduction.

Envelope schema_version=1 contains collected_at, snapshot_id, capture_sequence, source identity/hash, cohort interval/cutoff/revision, policy, provenance, producer_health, lifecycle counts/ratio/status, quality readiness and legacy_report (existing report schema_version=3). Thus the reducer schema remains compatible while the new envelope is explicitly versioned. Write effectiveness-latest.json by same-directory temp file + atomic replace. Append compact history only for a new source/registry/policy revision; repeated Stop notifications with unchanged evidence do not add duplicate snapshots.

Retain the newest 200 compact history records, maximum 1 MiB each, and four gzip archives of at most 200 records each. Oversized reports remain available as latest with evidence counts/hash in history; archive the oldest records, keep the newest records hot, and delete excess archives under the same lock. Bound collection errors to 100 records. Registry compaction may remove only finalized units already represented in retained snapshots; never prune pending units. Retain immutable source captures referenced by retained snapshots, with a 256 MiB total cap. Before publication, evict the oldest retained history record and its unshared capture together until the new capture fits; preserve latest and pending-unit state. Publish the reduced retention horizon explicitly. If the new capture plus protected state alone exceeds the cap, report COLLECTION_ERROR; ordinary history growth must not deadlock publication. Never leave a retained snapshot referencing deleted bytes. This does not rotate the original event log.

4. Readiness and outcome-quality contract

Decision precedence is COLLECTION_ERROR, UNSUPPORTED, STALE, DEGRADED (malformed/conflicting/unexpected/unattributed evidence), NO_OPPORTUNITY (no eligible or pending units), INSUFFICIENT_EVIDENCE (pending or eligible sample below policy), then READY or COVERAGE_BELOW_POLICY. Numeric ratios remain visible with their counts even when readiness prevents a passing claim. A missing population or broken collector never passes a threshold by coercing null to zero or one. The CLI emits a structured status; local automatic collection is observational and never blocks user work.

Preserve all five existing diagnostic components, including learning_quality. Do not gate on legacy overall_score or equate it with readiness. The broader evidence-collection work owns independent verification, guard ground truth, recovery outcome and learning cohorts. Each quality dimension must supply an independent opportunity manifest before being labeled measurable:

  • First pass: all eligible writes, including missing verification; independently verified first-attempt success / eligible writes. Missing checks are unknown, observed failed checks are failures, no writes is NO_OPPORTUNITY.
  • Recovery: all observed eligible errors, including unrecovered errors; independently verified recovery / eligible errors. No successful heals with known failed recovery is measured failure, not missing opportunity.
  • Prevention: precision/recall only for independently labeled decisions; report label coverage and keep calibration probes separate from ambient activity.
  • Learning: only comparable treatment/control evidence supports a measured effect; observational changes remain labeled observational, without causal claims.

These are readiness requirements, not permission to rewrite legacy formulas in the collector. Until the corresponding producer contract is implemented, show each quality dimension as unavailable with its exact missing evidence. Lifecycle readiness can be READY while quality readiness is unavailable.

5. CI evidence and verification

Add a normal step to the existing ci.yml test job. In a temporary initialized project, invoke the production session hooks and executor boundary adapters, run controlled subprocesses with known exit outcomes, and record an independent expected-unit manifest before execution. Read emitted events through the same collector used at runtime. No live LLM calls, personal telemetry upload or required local .dev-kit files. No hand-written matching events as the sole integration evidence. Pure reducer fixtures remain useful unit tests.

The probe artifact includes checked-out SHA, adapter versions, origin=ci-probe, expected manifest, raw redacted source capture, envelope and per-scenario verdict. Empty/missing artifacts, wrong SHA/origin, missing registered adapter, unexpected terminals, or collector errors fail this job. The ordinary job result is the check; no checks:write permission or actions/github-script check creation. Summary/artifact publication runs with always() so failed probes stay reviewable. Passing probes demonstrate instrumentation behavior under those scenarios, not effectiveness of developer activity absent from the CI runner.

Required acceptance scenarios:

  • Real adapter success, nonzero exit, blocked output and catchable exception preserve workflow outcome and emit exactly the expected lifecycle semantics.
  • Two Stop events keep a session pending; SessionEnd closes it once. A duplicate SessionEnd refresh does not duplicate history or semantic terminal events.
  • Killed owner, missed callback and monitor restart leave missing closure visible; late genuine termination revises the original enrollment cohort.
  • Cross-midnight completion joins the enrollment day; same subject ID in two runs/retries remains two units; an open long-running unit stays pending.
  • Missing start, terminal-only unit, missing whole adapter, malformed row and conflicting retry produce explicit non-ready states rather than a clean ratio.
  • Two worktrees never share registry or latest paths; module resolution still works when invoked outside the plugin checkout and paths contain spaces.
  • Concurrent emit/collect, lock timeout, crash before atomic replace, duplicate retry and out-of-order publication retain a coherent newest snapshot.
  • Empty runtime corpus is NO_OPPORTUNITY, too-small cohort is insufficient, known failed outcomes remain failures in quality evidence but valid paired closures in lifecycle coverage, and CI fixtures never inflate runtime coverage or quality readiness.
  • Missing independent verification, missing recovery outcomes and missing control cohorts remain unavailable even when legacy overall_score is numeric.
  • Archive boundaries, capture storage cap and stale-cache display obey the documented limits, including collector failure without workflow failure.

6. Delivery and sibling proposal boundary

Implement the population/envelope and coherent snapshot contract first, then lifecycle adapters plus monitor, then automatic consumers and CI probes. The release criterion is the acceptance matrix above passing on each declared supported runtime; unsupported lifecycle semantics must remain visible. This PR changes proposal YAML and rendered HTML only; it does not claim those contracts are already implemented or validated as production behavior.

evidence-collection remains the design for broader producer quality. It also contains historical statements that need revalidation against the current reducer; do not import its old score assumptions as facts. Auto-collection owns lifecycle population, automatic scheduling, provenance and storage. Quality producers supply their independent manifests into that contract. No duplicate session instrumentation or speculative statusline files are added.

Before / After

Before (current state)

The repository already emits session and executor lifecycle events and computes a five-component diagnostic report. The missing capability is a trustworthy, automatic measurement contract: a known population, a closed observation window, producer health, consistent source reads, and explicit unavailable evidence. Merely running the existing reducer at Stop does not establish those properties.

Evidence

  • lib/harness_effectiveness.py::_subject_observability: joins distinct subject_id sets across the entire corpus, accepts completed/failed/blocked terminals, exposes score on 0–100 and coverage on 0–1. An empty union has score=null; unrelated non-lifecycle events do not create a denominator.
  • lib/harness_effectiveness.py::build_report: schema_version=3; weighted overall uses only non-null components. A numeric overall is not evidence that all five dimensions were measured. _integrity independently rereads events.jsonl after read_events.
  • lib/execute.py::_step_post_collect: already emits step.blocked, step.failed and step.completed. The old proposal incorrectly described nonzero/blocked exits as missing terminals. Unexpected exceptions outside those branches still need lifecycle tests.
  • hooks/session-start-check.sh emits session start; hooks/trace-session-end.sh runs on both Stop and SessionEnd and skips after any terminal. A per-turn Stop can therefore prematurely close a session. Separate hook processes cannot share a Python context manager.
  • hooks/lib/payload-parse.sh: emits guard decisions with ground_truth=unlabeled; it does not prove that every tool invocation starts a lifecycle subject.
  • lib/trace_log.py::append_event: event validation/redaction exists, duplicate event IDs are regenerated and lock failures can fall through. This is not semantic retry idempotency or a coherent multi-reader snapshot contract.
  • .github/workflows/ci.yml is the existing CI entrypoint. .github/workflows/pr-verify.yml, commands/statusline.md and skills/statusline/SKILL.md do not exist in the reviewed PR tree.
  • lib/eval_runner.py already imports build_report; skills/harness-effectiveness/SKILL.md exposes the same diagnostic reducer. The sibling evidence-collection proposal owns broader producer quality work.
  • The previous 54,307-event / 0.4% claim has no committed corpus, cutoff, producer grouping or reproducible artifact. It is not used as a baseline or proof of a particular producer defect.

After (proposed state)

Add one automatic measurement service around the existing event store. It owns a versioned collection envelope and lifecycle registry, consumes a consistent source snapshot, and publishes per-worktree results after real workflow boundaries. Keep the existing five-component report as a clearly labeled legacy diagnostic. The primary automatic result is lifecycle coverage plus measurement readiness, not an unqualified effectiveness score. Missing outcomes remain missing.

CI executes production adapters against known process outcomes and checks their recorded evidence. It gates the instrumentation contract, not the developer's unavailable local history. Runtime cohorts are observed separately and never padded with CI fixtures. Broader quality scores become ready only when their independent outcome evidence and opportunity denominators are present.

Pros

  • An independently enrolled population makes missing start and missing terminal evidence visible; a missing producer cannot improve coverage by shrinking the event denominator.
  • Lifecycle closure, evidence readiness and observed quality are separate results with explicit counts and provenance.
  • Automatic hooks and a bounded monitor cover normal completion and missed callbacks; CI verifies production instrumentation with independently known outcomes.
  • One immutable input capture supports reproducible reports and safe concurrent writers without changing legacy diagnostic formulas.

Cons

  • Accurate measurement requires registry and monitor state in addition to the existing reducer; it is more work than a periodic shell invocation.
  • A finite lease can expire during a long runtime pause. Expiry records missing observation, and late real evidence produces a revised snapshot with the previous snapshot retained.
  • Per-worktree capture of a large legacy trace is linear work; collectors coalesce repeated requests and do no reducer work in a display callback.

Limitations

  • No local process can observe events while the host is powered off. Monitor loss is exposed by stale freshness; recovery collection runs automatically at the next supported boundary.
  • SIGKILL/OOM cannot guarantee a terminal event. Timeout proves that closure was not observed by a cutoff; it does not prove task failure or success.
  • Lifecycle coverage is not usefulness, correctness, prevention precision or causal learning benefit. Those require separate evidence under the sibling proposal.
  • The existing all-history subject_observability diagnostic remains coarse and may collapse repeated subject IDs; it is not the new attempt-level measurement or gate.
  • This proposal specifies local collection and CI probe artifacts, not a telemetry upload service or a new HUD implementation.
