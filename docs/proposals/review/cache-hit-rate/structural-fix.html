Executive summary

dev-harness-kit's tools/token_efficiency_analyzer.py (last 30d, 2,581 sessions) reports 96.1% aggregate cache hit — but the distribution hides a structural problem: 1,952 of 2,469 sessions (79%) are 1-3 calls long and average 20.0% cache hit, while 331 long-running sessions (30+ calls) average 96.1%. The 520 warnings include 129 CACHE_HIT_LOW (cache hit <50%) and 72 REPEATED_USER_MSG (user-message echo, direct evidence of prefix drift).

rules/session-hygiene.md already encodes Iron Laws 1, 3, 6 that explain why this happens — but those rules have no automated enforcement beyond the analyzer's warnings. The proposal closes the loop with 4 ordered fixes that surface prefix drift per surface (hook / system-reminder / skill / sub-agent / model switch) and let the existing warning codes drive a fix-it pass.

Net verdict: ship F1 + A1 + A2 (diagnostic + hook audit + skill frontmatter audit) as Phase 1. Defer D / E / G to Phase 2 gated on Phase 1 hit-rate movement. Net token delta: +~280 lines (analyzer extension + audit patches + tests). Stale cost surface (stale_cost_usd=$2,067.00 / $2,383.96 = 86.7%) suggests a parallel stale-worktree-cleanup carve-out is also worth its own proposal — out of scope here.

Problem statement

What the data shows

bucket           n_sess    in (M)   cache_read (M)   hit%
1-3 (short)       1,952      7.2       1.8           20.0%
4-10                112      3.7       4.9           57.2%
11-30                75     10.9      51.1           82.4%
30+                 331  1,251.6  31,073.4           96.1%

Long sessions hit 96% because Anthropic's prompt cache amortizes across many turns. Short sessions do not hit because they exit before turn 2 — the cache_write from turn 1 is wasted, and turn 1's input_tokens (non-cached) is the whole session.

Why short sessions exist

The repo has structural patterns that cause short sessions:

  • `/clear` reflex — users reach for /clear when context grows, resetting the cached prefix instead of /compact-ing.
  • *Single-shot `/dev-kit: invocations** — many slash commands (docs-maintenance, token-analyzer, inspect`) finish in 1-3 turns; each is a cold start.
  • Worktree churn — every worktree switch can be a fresh session with no carry-over prefix (cwd + recent commits change).

Why long sessions still drop below 96%

The 129 CACHE_HIT_LOW warnings in long sessions are caused by prefix drift within an otherwise-cacheable session:

  • Hook stdout — every dev-kit hook (worktree-guard, log-on-session-start, tdd-guard, notification-collapse, secret-scan, loop-detect, …) emits content that becomes part of the prompt prefix. If even one byte of that output changes between turns, the entire cache namespace is invalidated. The 72 REPEATED_USER_MSG warnings are direct evidence of this — hook stdout echoing content already in context.
  • System-reminder re-injection — <system-reminder> blocks (total_tokens, currentDate, gitStatus) are re-emitted by Claude Code on every turn; they sit at the top of the prefix and are intended to be volatile, so the cache re-validation cost is paid every turn regardless of whether anything actually changed.
  • Skill frontmatter non-determinism — if a skill's SKILL.md frontmatter includes a build-time hash, a generated slug, or a timestamp, the cache namespace is unique per build (no reuse across sessions even with identical content).
  • Sub-agent context inheritance — agents spawned via the Agent tool inherit the parent's full prompt, including all the parent's volatile prefix. The sub-agent then has no chance of cache hit on its own prompt because its prefix is parent-specific.
  • Mid-session model switch — Anthropic maintains separate cache namespaces per model. Switching Sonnet→Opus (or vice versa) mid-session forces a cold start. MODEL_OVERSPEC warns about 3 such cases.

Option A selection rationale:

  • F1 (cache_decay diagnostic) is the prerequisite for every other fix. Without it, we cannot tell whether a 96% hit-rate session is hitting on every turn (stable prefix) or only on turn 2 then dropping to 50% (drifting prefix). The existing analyzer already emits cache_hit_ratio per session but not the per-turn curve.
  • A1 (hook stdout audit) is the highest-leverage single fix. The repo has 18 hooks under hooks/*.sh; many of them emit deterministic state but the analysis couldn't be done without F1 to confirm which hooks are actually bleeding the prefix.
  • A2 (skill frontmatter audit) has the same prerequisite. Once F1 shows where the prefix is breaking, A2 is a 1-day pass over the 39 skills with a deterministic-content check.

Options B/C are deferred: B is high-impact but requires testing the cache_control boundary semantics on Anthropic's API (not just dev-kit's surface); C is pure documentation, which doesn't move the metric.

Recommended approach — 4 ordered fixes

F1 — Cache decay diagnostic in tools/token_efficiency_analyzer.py

Add a new per-session field cache_decay: list[float] — cache_hit_ratio per turn index (1..N). Bucket sessions by length into the 4 buckets already used in the HTML output. Emit a new HTML tile "Cache hit ratio vs turn index" that overlays all sessions in the window (median, p25, p75 lines per bucket).

Pseudocode:

# in tools/token_efficiency_analyzer.py
def cache_decay(per_turn_cache_read, per_turn_input):
    out = []
    for cr, inp in zip(per_turn_cache_read, per_turn_input):
        total = cr + inp
        out.append(cr / total if total else 0.0)
    return out

A1 — Hook stdout audit + volatile-field strip

For each of the 18 hooks under hooks/*.sh that fires per-turn, audit stdout for volatile content (timestamps, PIDs, ephemeral session IDs, randomized build slugs). Replace volatile output with stable strings OR route the volatile data through the tool result body (where it is still seen by the model) instead of the hook stdout (where it sits in the prefix).

Target hooks (preliminary list, refine after F1 ships):

  • hooks/worktree-guard.sh (PreToolUse, 159 LOC) — emits routing context on every Edit/Write; check for ephemeral paths
  • hooks/log-on-session-start.sh (SessionStart, 131 LOC) — fires once but its output should be byte-stable across runs
  • hooks/notification-collapse.sh (PostToolUse, 83 LOC) — emits per-turn deduplication state
  • hooks/loop-detect.sh (PostToolUse, 76 LOC) — emits per-turn fingerprint counts

Acceptance: hook stdout bytes are identical between two sequential invocations against the same repository state.

A2 — Skill frontmatter determinism audit

For each of the 39 skills under skills/*/SKILL.md, audit frontmatter for non-deterministic fields. The version-from- plugin-json feedback already establishes the discipline for version strings; extend it to "no timestamps, no build hashes, no auto-generated slugs."

Audit script (small, ship with the analyzer):

# scripts/audit_skill_frontmatter.py
FORBIDDEN = re.compile(r'(\d{4}-\d{2}-\d{2}|\b[0-9a-f]{7,}\b|build[-_]?\d)')
for path in glob('skills/*/SKILL.md'):
    fm = read_frontmatter(path)
    hits = FORBIDDEN.findall(fm)
    if hits: print(f'{path}: {hits}')

D / E / G — Deferred to Phase 2 (gated on Phase 1 metric)

  • D — Sub-agent prompt isolation: when the orchestrator spawns an Agent, pass only the task. Sub-agent pays cache_write once for its clean prefix. Defer: requires agreement on which parent context fields are "volatile vs stable."
  • E — `cache_control: { ttl: "1h" }` markers in dev-kit's own skill loader. Defer: needs Anthropic API testing for behavior when a sub-agent under cache_control-1h re-asks after TTL.
  • G — One-model-per-session lock. Defer: the existing MODEL_OVERSPEC warning (3 sessions) is small enough that a docs reminder is probably cheaper than a hook.

Thin-harness memo

  • Hook stdout audit (A1): ADOPT — rules/session-hygiene.md Iron Law 3 ("Volatile content stays in the prompt tail, never the prefix") already names the failure mode; A1 turns it into a testable contract.
